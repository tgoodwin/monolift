### Summary

- **Path length:** 8 steps (entrypoint → region root).
- **Edge types encountered:** `direct-function-call`, `method-call-on-concrete-type`, `function-value-in-struct-field`, `http-handler-registration`, `closure-capture` + `direct-call-on-local-function-value`.
- **Hardest edge:** Step 3 (the urfave/cli `Action` dispatch) and Step 6 (the `web.Router.Post` registration) are the two non-trivial edges. Both are forms of "function value stored in a data structure, then invoked by a framework loop based on input keying" — the cli framework keys on argv, the router on (method, path). Step 6 is arguably harder in practice: there are hundreds of registration sites in `api.go` alone, the variadic `h ...any` parameter erases handler-typed arguments to `interface{}`, and an analyzer must specifically understand that the *last* variadic element is the terminal handler while the earlier ones are middleware. Step 3 is more contained: `Action` is a single named field on a single concrete type, and field assignments to it are easy to enumerate in the source tree.
- **Static-analysis feasibility:** Resolvable end-to-end without any dynamic gap. There is no `reflect.Call`, no plugin loading, no runtime-loaded function pointer between `main()` and `MigrateRepository`. The path requires (a) struct-field-flow analysis for `cli.Command.Action`, (b) variadic-arg flow analysis for the `web.Router.Post`-style registration helpers, and (c) ordinary call-graph construction elsewhere — all standard whole-program analysis. The argv-based and path-based selections produce non-determinism in *which* path executes, but the reachability set is fully decidable.
- **Alternative paths (briefly):** The web UI route `m.Get("/migrate", repo.Migrate)` at `routers/web/web.go:1059` (different `repo` package — `routers/web/repo`) is a sibling entry that ultimately reaches `MigrateRepository` via a longer detour: `routers/web/repo/migrate.go:247` → `services/task/task.go:60` (`task.MigrateRepository`) → an internal task queue → `services/task/migrate.go:123` → `migrations.MigrateRepository`. That path adds an extra `function-value-in-struct-field` (the task-handler registration in the queue) and a `goroutine-launch` / `channel-send-receive` boundary at the queue runner, so it is strictly longer and harder than the API path traced above.
