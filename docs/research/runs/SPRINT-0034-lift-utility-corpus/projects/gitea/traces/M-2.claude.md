### Summary

- **Path length:** 11 steps.
- **Edge types encountered:** `direct-function-call`, `struct-literal-field-assignment`, `function-value-in-struct-field`, `higher-order-function-pass`, `closure-literal`, `callback-registration`, `goroutine-launch`, `interface-method-dispatch`, `channel-send-receive`.
- **Hardest edge:** Step 9–10, the `q.safeHandler` → `w.origHandler` chain. Two struct-field function values must be resolved back to their initialization site (a closure literal in `NewWorkerPoolQueueWithContext`, then a constructor parameter that was the closure literal in `archiver.Init`). A static analyzer needs both (a) confidence that these fields are write-once and (b) interprocedural propagation of the closure literal through `queue.CreateUniqueQueue` → `createWorkerPoolQueue` → `NewWorkerPoolQueueWithContext` to identify which concrete handler is invoked for *this particular* queue instance. (Step 7's interface dispatch is also non-trivial, but `RunCanceler` has a small set of implementers and `RunWithCancel` only sees one type flow in for the archiver path.)
- **Static-analysis feasibility:** Yes — the entire path is statically resolvable with whole-program type analysis plus closure/function-value tracking through struct fields and constructor parameters. There is no `reflect.Call`, `plugin`, or runtime-supplied function pointer on this path; everything is determined at link time. Resolving the specific archiver handler instance does require monomorphizing the generic `WorkerPoolQueue[*ArchiveRequest]` and tracking which handler closure was passed to *its* constructor — i.e., per-instance flow-sensitivity, not just per-type. The data flow into `doArchive`'s second argument additionally requires noting that `*ArchiveRequest` items reach the worker via the `q.batchChan` channel after being pushed by `archiverQueue.Push` from `StartArchive` (called from `(*ArchiveRequest).Await` at `archiver.go:92`); but that is data flow, not call-graph dispatch.
- **Alternative paths considered:** `doArchive` is referenced from production code only at `archiver.go:237` (the handler closure). Other references at `archiver_test.go:83/84/85/89/104/112` are test-only direct calls (no binary entrypoint). `Stream` (`archiver.go:120`) is a sibling code path that also generates archive bytes, but it does *not* call `doArchive` — it is invoked from inside the handler closure (line 203) and bypasses the `repo_model.RepoArchiver` bookkeeping, so it is not an alternative path to the region root. There is no shorter path.
