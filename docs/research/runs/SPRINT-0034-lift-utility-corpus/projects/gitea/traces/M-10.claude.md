### Summary

- **Path length:** 13 steps.
- **Edge types encountered:** `direct-function-call`, `function-value-in-struct-field`, `struct-literal-field-assignment` (Action registration in cli command literal), `function-value-parameter-invocation`, `function-value-stored-in-struct-field` (handler registration into the queue), `goroutine-launch` (twice — queue run-loop and worker), `method-call-on-concrete-type`, `interface-method-dispatch` (`RunCanceler.Run`), `channel-send-receive` (`q.batchChan`), `closure-capture` (`safeHandler` over `w`), `generic-type-parameter-instantiation` (`WorkerPoolQueue[[]*PushUpdateOptions]`).
- **Hardest edge:** Step 12 — the `q.origHandler(t...)` call inside `safeHandler`. The field is written exactly once per queue, but the worker code is generic over `T` and over which queue is using it. To say "this particular call resolves only to `services/repository.handler`" the compiler needs *instance-sensitive* field analysis: it must distinguish the `pushQueue` instance from every other `*WorkerPoolQueue` in the program. Without that distinction, the call edge fans out to every handler ever registered with `CreateSimpleQueue`/`CreateUniqueQueue`. Step 7 (the symmetric registration) is the same problem viewed from the other side. Note that there is no callable path from `PushUpdate`/`PushUpdates` to `pushUpdates` that bypasses the queue — the only enqueue point (`pushQueue.Push` at `push.go:73`) hands the batch over via `q.batchChan`, so the channel-mediated worker hop is unavoidable.
- **Static-analysis feasibility:** Fully resolvable. Every edge is a standard Go-level mechanism (direct calls, function-value fields, interface dispatch, goroutine launch, typed channel) — no `reflect.Call`, no plugins, no runtime-supplied function pointers. A field- and instance-sensitive call graph backed by a pointer/escape analysis (e.g. Andersen-style with allocation-site sensitivity for the `pushQueue` value) closes the loop. The single use of `reflect` along the path (`mustInitCtx` line 73) is for error logging only and does not affect dispatch. No alternative paths exist — `pushUpdates` is package-private and called only from `handler` (`push.go:38`), which is reachable solely through the queue worker described above.
