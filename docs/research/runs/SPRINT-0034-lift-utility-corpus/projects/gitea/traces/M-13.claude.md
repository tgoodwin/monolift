### Summary

- **Path length:** 8 steps (entrypoint → region root).
- **Edge types encountered:** `direct-function-call`, `method-call-on-concrete-type`, `function-value-in-struct-field`, `http-handler-registration`, `call-through-package-level-function-variable`, `function-value-in-package-variable`.
- **Hardest edge:** Step 5 (`http-handler-registration`). It requires the analyzer to model the router's registration API as "this function value is a reachable callee of the HTTP server" and to keep that knowledge through the chained `Mount(...)` calls in `routers/init.go:189`. Step 3 (`function-value-in-struct-field`) is structurally similar but easier because the struct field's type and dispatch site are stable across calls; routers carry per-route state that is harder for context-insensitive analyses to track.
- **Static-analysis feasibility:** Resolvable end-to-end with whole-program type analysis plus a model of (a) `urfave/cli` `Command.Action` dispatch and (b) the `web.Router` registration API. No `reflect.Call`, plugin loading, or runtime-supplied function pointer appears on this path. The `var Send = send` indirection (step 8) is the only point where flow sensitivity matters, and even there a single static initializer makes the resolution safe in the absence of a rebinding (which exists only in tests).
- **Alternative paths considered (not the shortest):** The mail queue path goes `runWeb → routers.InitWebInstalled (routers/init.go:128) → mailer.NewContext (services/mailer/mailer.go:25) → closure literal at mailer.go:48 registered with queue.CreateSimpleQueue → WorkerPoolQueue worker invokes the handler field on each pulled message → closure body calls sender_service.Send at mailer.go:52 → send`. That route adds two extra resolution edges (`closure-passed-as-handler-argument` plus `function-value-in-struct-field` for the queue's `handler` field at `modules/queue/workergroup.go:103` `q.safeHandler(batch...)`) compared with the direct HTTP handler path used above. It is the path exercised by ordinary outbound mail (`SendAsync` → queue → handler closure), whereas the chosen path is exercised by the admin "Send Test Email" button.
