## Critique of codex's trace

### Path
- **Correct:** yes — every file:line citation verifies. Path is `main → RunMainApp → app.Run → runWeb → serveInstalled → InitWebInstalled → mustInit → indexer_service.Init → code_indexer.Init → handler closure → index`, which is the canonical static route.
- **Minimal:** partially — codex's Step 6 collapses queue registration *and* worker dispatch into one edge ("queue-worker-callback-registration"), then Step 7 jumps directly from the closure body to `index`. That under-counts: registering a handler does not by itself reach the closure body; the worker goroutine launched at `modules/indexer/code/indexer.go:195` and the `safeHandler`/`origHandler` field call inside `modules/queue/workerqueue.go` and `modules/queue/workergroup.go:103` are the edges that actually activate the closure. Codex's resolution-notes paragraph mentions these lines but does not surface them as path steps, leaving an unmodelled gap between registration and invocation.

## Critique of gemini's trace

### Path
- **Correct:** no — many citations are off, and the path mixes producer (Push) and consumer (worker dispatch) edges. Specifically:
  - `main.go:34` cites `setting.AppVer = Version` inside `init()`, not `main`. `main` is at line 39; the call to `cmd.RunMainApp` is at line 45.
  - `cmd/main.go:167` cites `return err`, not `app.Run` (which is at line 160).
  - `cmd/web.go:303` for `runWeb` is wrong (correct: line 251); `cmd/web.go:330` for `serveInstalled` call is wrong (correct: line 287); `cmd/web.go:257` for the `InitWebInstalled` call is wrong (correct: line 205).
  - `routers/init.go:170` for the `indexer_service.Init` argument-pass is wrong (correct: line 156).
  - `services/indexer/indexer.go:19` for `code_indexer.Init` is wrong (correct: line 18; line 19 is the unrelated `stats_indexer.Init` call).
  - Step 7 cites `modules/indexer/code/indexer.go:134` as `indexerQueue.Push` — line 134 is `CreateUniqueQueue`. The actual `Push` call from populate is at line 298.
  - Step 8's "From" cites line 134 again for "queue worker retrieves the item"; the worker dispatch lives in `modules/queue/workergroup.go:103` calling `safeHandler`, none of which gemini cites.
- **Minimal:** no — Steps 6 and 7 (goroutine launch of `populateRepoIndexer` → `indexerQueue.Push`) are off-path. They describe a *producer* of queue items, not the consumer path that activates `index`. The minimal consumer path is: registration → worker goroutine started by `graceful.GetManager().RunWithCancel(indexerQueue)` at `modules/indexer/code/indexer.go:195` → `WorkerPoolQueue.doWorkerHandle` → `safeHandler` field call → `origHandler` field call → closure body → `index`. Gemini's path conflates "who puts items in the queue" with "who calls the handler". Steps 6–7 should be dropped; Step 8 should cite the actual worker invocation site.
- Steps 3 and 4 each silently compress two distinct cross-package direct calls into a single edge (`runWeb→serveInstalled→InitWebInstalled` and `mustInit→indexer_service.Init→code_indexer.Init`), which understates path length and hides the `mustInit` callback edge entirely.

### Other notes
- Gemini does not cite any code outside `evaluation/gitea/modules/indexer/code/indexer.go` for the queue dispatch, so the `WorkerPoolQueue` mechanism (`safeHandler`/`origHandler`/`doWorkerHandle`) is invisible in the trace. This is the part of the path most worth modelling, and it's missing.
- Resolution-notes are sparse and do not explain *what* the static analyzer must do at the hard edges.

## Cross-trace observations

All three traces converge on the same backbone (cli dispatch → web init chain → mustInit → indexer service → code indexer → queue handler → `index`), but they diverge sharply on (a) where the path *ends at registration vs. invocation* and (b) granularity of the indirection edges. Codex compresses the queue's register-and-dispatch into one composite edge and skips the worker goroutine; gemini detours through the producer side (`populateRepoIndexer` + `Push`) and conflates that with the consumer dispatch, while also accumulating wrong line numbers throughout. My own trace is closest to the canonical minimal path because it (1) keeps registration and worker invocation as two separate edges grounded in `workerqueue.go` and `workergroup.go`, and (2) uses lower-level edge labels (`function-value-in-struct-field`, `function-value-as-parameter`, `function-value-call-via-parameter`, `closure-capture`) that name compiler-resolution mechanisms rather than framework concepts.
