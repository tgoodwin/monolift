### Summary

- **Path length:** 9 steps from `main` to the region root.
- **Edge types encountered:** `direct-function-call`, `function-value-in-struct-literal-field`, `indirect-call-through-struct-field`, `http-handler-registration` (variant of `function-value-passed-as-argument`), `interface-method-dispatch` on `http.Handler.ServeHTTP`.
- **Hardest edge:** Step 7 / Step 8 — the http-handler registration / chi dispatch pair. The handler is passed through a variadic `any` slice, wrapped in a closure inside `wrapMiddlewareAndHandler`, stored in chi's routing trie keyed by URL pattern, and later invoked through the `http.Handler` interface. A naive call-graph builder loses the connection unless it (a) tracks values through `[]any`, (b) understands that chi stores handlers and dispatches them via `ServeHTTP`, and (c) connects the URL pattern at registration to the call site at dispatch. The cli `Action`-field edge (Step 2/3) is structurally similar but simpler because the field is typed and assigned exactly once per subcommand literal.
- **Static-analysis feasibility:** Feasible end-to-end. Every edge is a function value bound by name at a statically determined site (struct literal, `m.Get` argument, direct call). No `reflect.Call`, no `plugin.Open`, no runtime-supplied function pointers, no goroutine-only paths needed for this route. A whole-program analysis with type-flow through `any`/interface values and a small framework model for `urfave/cli/v3` and `go-chi` can statically connect `main` to `GetDiffForRender`.
- **Alternate (longer) paths:** The same region is also reached from `routers/web/repo/compare.go:506` (`CompareDiff` handler, registered at `routers/web/web.go:1268`/`:1270`) and `routers/web/repo/pull.go:805` (pull-request file viewer handlers registered around `routers/web/web.go:1624–1625`).
