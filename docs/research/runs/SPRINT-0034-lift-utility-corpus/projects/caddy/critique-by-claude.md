# Critique of caddy drafts by claude

## Verdicts on codex's draft

| Candidate ID | Verdict | One-paragraph reasoning |
|---|---|---|
| C-1 (encoding stream `responseWriter.Write` @ `modules/caddyhttp/encode/encode.go:313`) | MODIFY | The encoding work is real, but `responseWriter.Write` is the wrong granularity: every per-chunk `Write([]byte)` would become a network round trip, which dominates any compression saving. The cleaner lift root is the middleware boundary `Encode.ServeHTTP` at `modules/caddyhttp/encode/encode.go:154` (or, finer-grain still, the encoder's `Encoder.NewEncoder` + a buffered-body compress) — same compute envelope, but with one in/one out instead of streaming per-write coupling. Without that change codex's framing fails the rubric on Coherent Unit and Latency for the same reason claude's own C-4 only rates medium confidence. |
| C-2 (`HTTPBasicAuth.correctPassword` @ `modules/caddyhttp/caddyauth/basicauth.go:165`) | KEEP | Coherent Unit is even stronger than claude's C-1 framing of `Authenticate`: `correctPassword(account, plaintext) → (bool, error)` is value-typed and pure modulo the replica-local hash cache. Same Argon2id/bcrypt CPU envelope as C-1, same bursty-login load profile. Pointing at the inner method instead of the outer middleware is the right call. |
| C-3 (`funcMarkdown` @ `modules/caddyhttp/templates/tplcontext.go:350`) | KEEP | Identical pick to claude C-3 / gemini #1. Pure `string → (string, error)`, heavy goldmark+chroma per call, replica-local buffer pool. Textbook positive on all five rubric criteria. |
| C-4 (`caddyfile.Adapter.Adapt` @ `caddyconfig/caddyfile/adapter.go:32`) | DROP | Fails criterion 2 (Variable/spikable load): config adaptation runs at boot and on admin `/load` reloads — the rubric's exact "uniformly low-traffic" negative example, where lift overhead exceeds benefit. Also abuts the explicit exclusion "Initialization functions whose work happens once at boot." Codex itself rates Load Profile only "maybe" and admits this is control-plane work; that should have been disqualifying. |
| C-5 (`(*Templates).executeTemplate` @ `modules/caddyhttp/templates/templates.go:455`) | KEEP | Same region as claude C-2 / gemini #2 but at the inner `executeTemplate` rather than the outer `ServeHTTP`. The inner method is a strictly cleaner lift root because the buffered-body and request scope are explicit arguments rather than pulled out of `ResponseRecorder`. Both framings can coexist in the merged set; codex's is tighter. |
| C-6 (`(*FileServer).serveBrowse` @ `modules/caddyhttp/fileserver/browse.go:78`) | MODIFY | The directory-listing work is real but `serveBrowse` mixes redirect handling, conditional-GET, content negotiation, and template rendering — codex itself rates Coherent Unit "maybe" and notes that `loadDirectoryContents` is the cleaner sub-target. Modify the region root to `loadDirectoryContents` at `modules/caddyhttp/fileserver/browse.go:119`: that's where the entry stat/symlink/sort/limit work actually lives, with a clean `(ctx, fs, dir, root, urlPath, repl) → (listing, error)` shape and no HTTP-response-protocol coupling. |
| C-7 (`(*Handler).doActiveHealthCheck` @ `modules/caddyhttp/reverseproxy/healthchecks.go:391`) | DROP | Fails criterion 4 (State Independence): the probe mutates `upstream.Host` health counters via `markUnhealthy`/`markHealthy` closures (`healthchecks.go:464`/`485`) and emits `h.events` — exactly the rubric's "in-process pub-sub fan-out where every replica must see every event" negative. Also fails criterion 1 (Compute Envelope): each probe is one HTTP GET plus an optional regex over a body bounded by `MaxSize`; CPU per call is sub-millisecond. Lifting this splits health truth across replicas and pays a network hop for nothing. |
| C-8 (`SRVUpstreams.GetUpstreams` @ `modules/caddyhttp/reverseproxy/upstreams.go:122`) | DROP | Codex itself quotes the source comment that this "should be very fast and stable" and "may be called multiple times per request" — that is a direct disqualifier on criterion 5 (Latency tolerance: tight synchronous request path). Cache hits are O(1) and the only meaningful per-call work is a DNS SRV lookup gated by freshness checks; lifting that single DNS call is not a productive use of the lift mechanism. The global `srvsMu`/`srvs` cache (`upstreams.go:126`) also creates per-replica freshness divergence on top of the latency problem. |
| C-9 (`InternalIssuer.Issue` @ `modules/caddytls/internalissuer.go:103`) | KEEP | Same region as claude's C-5; codex got the file path right (`caddytls/internalissuer.go`, not `caddypki/`). Real signing work, certmagic-defined value-typed contract, bursty on-demand-TLS load, latency-tolerant caller. The signing-key-custody concern flagged in claude's C-5 still applies but is a deployment tradeoff, not a rubric failure. |

## Overall observations

The trio cleanly converges on the templates cluster (`funcMarkdown`, `executeTemplate`/`Templates.ServeHTTP`) and the basic-auth credential check, with codex's framings (`correctPassword`, inner `executeTemplate`) being slightly tighter than claude's (`Authenticate`, outer `ServeHTTP`); both should appear in the merged set. The drafts diverge most sharply on the control plane: gemini takes four control-plane picks (`Adapt`, `genRoot`, `Tokenize`, plus `ApplyTo`/`Rewrite` framed as compute), all of which fail criterion 2 because they are either boot-time or request-path-but-tiny — gemini is systematically less rigorous on Load Profile and on the "trivial helper" exclusion under Compute Envelope, and also has two off-by-many citation errors (`celmatcher.go:193`, `headers.go:167`) suggesting the file:line numbers were not opened. Codex is rigorous on shape but reaches into reverse-proxy plumbing (`doActiveHealthCheck`, SRV upstreams) where State Independence and the explicit "should be fast" caller contract bite. Net: gemini's draft drops to 3 keepers, codex's to 5 keepers plus 2 modifies; the hard signal is that all three of us should end up around the same five regions once the rubric is applied uniformly.
