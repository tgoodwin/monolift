- For the activation-path question (does a static analyzer see this call site exists?): yes, given a `text/template` model. For frequency analysis: only fires when user templates contain a markdown directive.

### Summary

- **Path length:** 11 steps (entrypoint → region root).
- **Edge types encountered:** `direct-function-call`, `function-value-in-struct-field` (cobra `RunE`), `closure-capture`, `interface-method-dispatch` (`caddy.App`, `caddyhttp.Handler`, `caddyhttp.MiddlewareHandler`, `http.Handler`), `goroutine-launch`, `http-handler-registration`, `method-call-on-concrete-type`, `struct-literal-field-assignment`, `method-value-into-keyed-map`, `reflective-call-via-string-keyed-funcmap`.
- **Hardest edge:** Step 11 — `text/template`'s reflective dispatch. The function value is statically pinned at the FuncMap registration site (Step 10), but the *key* that selects it (`"markdown"`) originates in a user-authored template file read at request time, not in any source-tree literal. Standard call-graph analysis cannot connect the two without modeling the template interpreter and reasoning about the contents of arbitrary external files. Step 7 (`MiddlewareHandler` dispatch downstream of JSON-config-driven module loading) is the runner-up: the concrete implementer is selected by config string ID, so the analyzer must either rely on a config snapshot or do a closed-world enumeration over all registered `http.handlers.*` modules.
- **Static-analysis feasibility:** Partially feasible. With a closed-world type analysis plus a model of cobra's `RunE` field and `text/template`'s FuncMap semantics, every step *up to and including* Step 10 is statically resolvable — and that line (`tplcontext.go:85`, where `c.funcMarkdown` is stored into the FuncMap) is the natural lift-instrumentation handle: a compiler can replace the stored method value with a dispatcher that consults the runtime oracle. The alternative is to instrument the `funcMarkdown` prologue itself. Either way, there is no purely-static call edge inside Caddy's source tree that reaches `funcMarkdown` directly — every production caller goes through the reflective FuncMap dispatch.
