## Activation path for caddy/M-1

Paths below are relative to `evaluation/caddy/`. The traced path is the normal `caddy run` HTTP-serving path with a native JSON configuration that selects the `templates` HTTP handler and a response body containing a `{{markdown ...}}` template action. Caddyfile adaptation is a longer alternative.

### Summary

- **Path length:** 21 steps
- **Edge types encountered:** `direct-function-call`, `command-registry-dispatch`, `configuration-keyed-module-registry-lookup`, `configuration-keyed-inline-module-lookup`, `closure-composed-middleware-chain`, `handler-field-assignment`, `interface-method-dispatch`, `http-server-handler-registration`, `method-call-on-concrete-type`, `interface-field-dispatch-to-closure`, `closure-captured-interface-dispatch`, `closure-composed-middleware-dispatch`, `direct-method-call-chain`, `method-value-in-function-map`, `interpreted-template-reflect-call`
- **Hardest edge:** Step 21, because `text/template` parses runtime response bytes and invokes the selected function through reflection. The static Go source exposes the possible `"markdown"` mapping, but not whether a particular response template contains that action.
- **Static-analysis feasibility:** The startup, module registration, HTTP app, route compilation, and middleware dispatch path is statically resolvable with whole-program type analysis plus models for Caddy's module registry and `net/http`; the final template-function call has a real dynamic gap unless the compiler deliberately over-approximates every function in the registered `FuncMap` or also analyzes the runtime template sources.

Longer alternatives exist. A Caddyfile configuration reaches the same handler through the directive registration at `modules/caddyhttp/templates/caddyfile.go:25`, the parser at `modules/caddyhttp/templates/caddyfile.go:36`, and the constructed `Templates` value returned at `modules/caddyhttp/templates/caddyfile.go:80` before converging on the native JSON route-handler path above. The template helper `httpInclude` can also re-enter the same server-side route pipeline from `modules/caddyhttp/templates/tplcontext.go:173`, but that is a recursive template-time path, not the shortest binary-entrypoint path to `funcMarkdown`.
