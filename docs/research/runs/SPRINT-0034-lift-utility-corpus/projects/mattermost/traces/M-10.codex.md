### Summary

- **Path length:** 11 steps.
- **Edge types encountered:** `direct-function-call`, `init-time-function-field-dispatch`, `method-call-on-concrete-type`, `goroutine-launch`, `channel-receive-type-switch`.
- **Hardest edge:** Step 10, because the call to `sendFile` is guarded by a receive from `[]chan any` plus a type switch. A precise static analyzer has to connect the `sendFileTask` value constructed in `SendFile` to the channel send in `enqueueTask`, then to the matching receive/type-switch branch in `sendLoop`.

The path has runtime gates for command selection, license/config, and task availability, but I did not find a `reflect.Call`, plugin-loaded function, or other dynamic-code boundary on the shortest production path.

The production task producer is the shared-channel attachment sync path: `platform/services/sharedchannel/attachment.go:102` calls `rcs.SendFile(...)` after creating the remote upload session. Tracing that producer from startup through `sharedchannel.Service.syncLoop` is longer than the remote-cluster worker activation path above, but it supports the same channel edge in Step 10 rather than forming a shorter route to the region root.
