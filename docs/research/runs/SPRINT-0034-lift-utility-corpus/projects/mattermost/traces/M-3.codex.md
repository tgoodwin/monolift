### Summary

- **Path length:** 14 steps
- **Edge types encountered:** `direct-function-call`, `struct-field-callback-dispatch`, `direct-method-call`, `handler-wrapper-construction`, `http-route-dispatch`, `function-value-in-struct-field`, `method-call-on-concrete-type`, `closure-capture-goroutine-launch`
- **Hardest edge:** Step 8, because resolving `POST /api/v4/posts` to `web.Handler.ServeHTTP` requires modeling the `net/http` server handler field plus Gorilla mux subrouter and method/path registration. Step 13 is also nontrivial because it crosses a closure passed to a goroutine helper, but the closure body is explicit.
- **Static-analysis feasibility:** The full path is statically resolvable in principle with whole-program type/dataflow analysis plus models for command callbacks, HTTP handler registration, and goroutine helpers; no true dynamic boundary is required.
