# Trace critique for mattermost/M-9 by codex

## Critique of claude's trace

### Path
- **Correct:** partially - The server-command route is real and most file:line citations check out. Step 9's title is misleading: `runJobs` is called inside `NewServer` at `server/channels/app/server.go:513-514`, before `server.Start()`, and Step 10 compresses the watcher/timer/map/channel path too aggressively.
- **Minimal:** no - It uses the normal `server` route rather than the shorter `jobserver` route that starts workers directly after initialization. It also collapses non-trivial watcher and channel edges that should remain explicit even if direct `StartWorkers`/`Workers.Start` calls are compressed.

### Edge types
| Step | claude's label | Verdict | Suggested label (if different) | Reasoning |
|---|---|---|---|---|
| 2 | `function-value-in-struct-field` | RENAME | `registered-struct-field-callback` | Cobra reaches `serverCmdF` through the `RunE` field populated during init/command registration; the registration context matters, not just an arbitrary field-held function. |
| 7 | `closure-capture` + `struct-literal-field-assignment` | RENAME | `closure-capture-into-struct-field` | The relevant static edge is one closure value capturing `appInstance`/`storeInstance` and being stored in `SimpleWorker.execute` via `NewSimpleWorker`. |
| 8 | `interface-upcast-into-container` | RENAME | `constant-keyed-interface-container-store` | The interface upcast is real, but the critical later resolution also depends on storing the worker under constant key `model.JobTypeRecap`. |
| 9 | `interface-method-dispatch` through a map, combined with `goroutine-launch` | RENAME | `map-iteration-interface-dispatch-and-goroutine-launch` | `Workers.Start` iterates `map[string]model.Worker`; resolving `go w.Run()` requires connecting the recap map entry to `*SimpleWorker` and crossing the goroutine launch. |
| 10 | `channel-send-receive` + `method-call-on-concrete-type` | SPLIT | `timer-driven-method-call`, `map-keyed-interface-dispatch-through-channel`, `method-call-on-concrete-type` | The receive in `SimpleWorker.Run` is driven by `Watcher.Start`'s timer, `PollAndNotify`, `workers.Get(job.Type)`, `worker.JobChannel()`, and a channel send. This is more than one edge. |
| 11 | `function-value-in-struct-field` | OK | - | Correctly identifies the `SimpleWorker.execute` field read as the edge that invokes the recap closure. |
| 13 | `interface-method-dispatch` | OK | - | `appInstance` is statically `recap.AppIface`, with the production value flowing from `app.New(ServerConnector(...))` to concrete `*app.App`. |

### Other notes
The trace is a valid production alternative, but it is not the canonical minimal route I would use. The `server.Start` wording should be removed because the worker path is enabled by `app.RunEssentialJobs` during `NewServer`, not by `(*Server).Start`.

## Critique of gemini's trace

### Path
- **Correct:** no - The prefix through `recap.MakeWorker` and the tail from the closure body to `ProcessRecapChannel` are real, but the trace never reaches an invocation of the closure. It skips worker registration, map dispatch, goroutine launch, watcher polling, channel send/receive, `DoJob`, and `worker.execute`.
- **Minimal:** no - It is short because required non-trivial activation edges are omitted. Several citations are also off: `main` calls `commands.Run` at `main.go:20`, `Run` starts at `root.go:15`, and `RootCmd.Execute()` is at `root.go:17`.

### Edge types
| Step | gemini's label | Verdict | Suggested label (if different) | Reasoning |
|---|---|---|---|---|
| 3 | `callback-registration` | RENAME | `registered-struct-field-callback` | The edge from Cobra execution to `serverCmdF` is specifically a function stored in `cobra.Command.RunE` during init and invoked by the command dispatcher. |
| 8 | `callback-registration` | WRONG | `closure-capture-into-struct-field` | The edge is backwards/incomplete: line 27 defines the closure, line 34 passes it to `jobs.NewSimpleWorker`, and `base_workers.go:32` stores it in `SimpleWorker.execute`. None of that invokes the closure. |
| Missing after 8 | - | MISSING | `constant-keyed-interface-container-store` | `RegisterJobType`/`AddWorker` stores the recap worker under `model.JobTypeRecap`; this key is needed to route pending recap jobs. |
| Missing before 9 | - | MISSING | `map-iteration-interface-dispatch-and-goroutine-launch` | `StartWorkers` calls `Workers.Start`, which iterates `map[string]model.Worker` and launches `go w.Run()` for enabled workers. |
| Missing before 9 | - | MISSING | `timer-driven-method-call`, `map-keyed-interface-dispatch-through-channel` | `Watcher.Start` polls on a timer, `PollAndNotify` looks up `workers.Get(job.Type)`, and sends the job to `worker.JobChannel()`. |
| Missing before 9 | - | MISSING | `method-call-on-concrete-type`, `function-value-in-struct-field` | `SimpleWorker.Run` calls `DoJob`, and `DoJob` invokes `worker.execute`; this is the actual entry into the recap closure. |
| 10 | `interface-method-dispatch` | OK | - | Once inside `processRecapJob`, the call to `appInstance.ProcessRecapChannel` is correctly an interface dispatch from `AppIface` to `*app.App`. |

### Other notes
`callback-registration` is too coarse for this corpus: it hides the difference between Cobra `RunE`, closure storage in a struct field, and constant-keyed worker-map registration. The skipped job-system edges are the core static-analysis challenge for this candidate.

## Cross-trace observations

Both traces converge on the server-command prefix and on the final `processRecapJob` to `AppIface.ProcessRecapChannel` interface dispatch. They diverge sharply in the middle: claude compresses the worker registration/scheduling/channel path, while gemini mostly omits it and jumps from closure construction to closure body. Claude is closest among the two foreign traces, but the canonical minimal path should retain the non-trivial worker map, goroutine, watcher, channel, and `execute` field edges; the jobserver route is the cleaner shortest production route.
