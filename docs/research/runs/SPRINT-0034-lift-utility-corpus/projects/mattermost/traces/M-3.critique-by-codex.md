# Trace critique for mattermost/M-3 by codex

## Critique of claude's trace

### Path
- **Correct:** partially - The path is mostly real and the cited source lines match this checkout, but Step 7 jumps from registration to HTTP runtime dispatch without an explicit `runServer` -> `server.Start()` -> `http.Server.Serve` edge.
- **Minimal:** no - Steps 12 and 13 can be collapsed into one closure/goroutine edge from `a.Srv().Go(func(){...})` to `handleWebhookEvents`; conversely, if path continuity is required, add the missing `server.Start()` edge before HTTP dispatch.

### Edge types
| Step | claude's label | Verdict | Suggested label (if different) | Reasoning |
|---|---|---|---|---|
| 2 | `function-value-in-struct-field` | RENAME | `struct-field-callback-dispatch` | The important edge is Cobra invoking a callback stored in `RunE` after package-init assignments, not merely a local field call. |
| 6 | `function-value-in-struct-field` / `http-handler-registration` | RENAME | `handler-wrapper-construction` | The step enters `APISessionRequired`, which constructs `web.Handler` and stores `createPost` in `HandleFunc`; route registration is adjacent but not the callee. |
| 7 | `interface-method-dispatch` | RENAME | `http-route-dispatch` | `http.Handler` interface dispatch is only part of the edge; the analyzer must also model `http.Server.Handler`, Gorilla mux route matching, and method/path registration. |
| 8 | `function-value-in-struct-field` | OK | - | This accurately describes `h.HandleFunc(c, w, r)` after the wrapper stored `createPost`. |
| 12 | `closure-capture` + `goroutine-launch` | RENAME | `closure-capture-goroutine-launch` | The split labels describe the mechanism, but the schema should treat the captured closure passed through `Server.Go`/`PlatformService.Go` as one reusable edge kind. |

### Other notes
`APISessionRequired` can optionally return a gzip wrapper depending on config; the canonical uncompressed path is acceptable if the model records that wrapper as an optional extra handler layer.

## Critique of gemini's trace

### Path
- **Correct:** partially - The high-level route is the right one, but Step 4 fabricates a registration-to-handler call and skips `APISessionRequired`, `web.Handler.ServeHTTP`, and the `HandleFunc` field call. Several line citations are stale: `main` is line 20, `InitPost` starts at line 23, the route registration is line 24, `createPost` calls `CreatePostAsUser` at line 130, `CreatePostAsUser` calls `CreatePost` at line 67, and `handleWebhookEvents` starts at line 37.
- **Minimal:** no - The trace is short because it omits necessary HTTP dispatch edges, while still keeping a separate closure-body step that can be collapsed into the goroutine-launch edge.

### Edge types
| Step | gemini's label | Verdict | Suggested label (if different) | Reasoning |
|---|---|---|---|---|
| 1 | `cobra-command-dispatch` | SPLIT | `direct-function-call` + `struct-field-callback-dispatch` + `direct-function-call` | One framework-named edge combines `main` -> `commands.Run`, `RootCmd.Execute()` -> `RunE`, and `serverCmdF` -> `runServer`; those are distinct mechanisms. |
| 4 | `http-handler-registration` | WRONG | `handler-wrapper-construction` + `http-route-dispatch` + `function-value-in-struct-field` | Registering `createPost` does not execute it. The real path stores it in `web.Handler.HandleFunc`, starts the HTTP server, dispatches through the mux to `ServeHTTP`, then calls the stored field. |
| 8 | `goroutine-launch` | RENAME | `closure-capture-goroutine-launch` | The edge must track the captured function literal through `Server.Go` and `PlatformService.Go` to the eventual `f()` invocation. |

### Other notes
`cobra-command-dispatch` is too framework-specific for the graph schema; prefer a callback/field-dispatch label plus optional notes naming Cobra. `http-handler-registration` is useful as a registration event, but not as an activation edge directly to `createPost`.

## Cross-trace observations

Both traces converge on the same intended path: CLI server startup, API4 post route registration, `createPost`, `CreatePostAsUser`, `CreatePost`, `handlePostEvents`, `handleWebhookEvents`, and `TriggerWebhook`. Claude is closest to the canonical minimal path because it preserves the handler wrapper and field-call edges; gemini captures the broad route but collapses the hardest HTTP activation boundary into a non-call edge. The main normalization point is to model HTTP registration, HTTP route dispatch, stored handler invocation, and closure/goroutine launch as separate reusable edge kinds.
