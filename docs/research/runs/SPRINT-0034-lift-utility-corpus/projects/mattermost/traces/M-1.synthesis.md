## Resolution notes

- **Step 2** (`function-value-in-struct-field`): cobra dispatches by reading the `RunE` field of `serverCmd`; the field is assigned exactly once in the struct literal at `server.go:30` (`RunE: serverCmdF`) and `init()` adds the subcommand. Per-allocation field tracking folds the field-load into the constant function reference `serverCmdF`. The `init()` timing is incidental — the resolver only needs to know the field was bound once.
- **Step 6** (`http-handler-registration`): the analyzer must model `gorilla/mux.Router.Handle(pattern, http.Handler)` as a sink that binds `pattern × method` to a function value. The handler flows from the named function `uploadFileStream` through `APISessionRequired` (`server/channels/api4/handlers.go:50`), which stuffs it into `web.Handler.HandleFunc` at `handlers.go:53`; later `web.Handler.ServeHTTP` (`server/channels/web/handlers.go:145`) invokes that field at `:355`. This single edge collapses the interface dispatch (`http.Handler.ServeHTTP` resolves to `web.Handler` — only implementation reaching this binding) and the function-field load into the registration sink.
- **Step 9** (`closure-capture` + `goroutine-launch`): two coupled mechanisms. (i) The closure literal at `app/file.go:861–866` captures the receiver `a *App` and the local `infoCopy`. (ii) The `func()` value is forwarded twice — `Server.GoBuffered(f)` → `PlatformService.GoBuffered(f)` — before reaching `go f()` at `goroutines.go:36` which calls `f()` at `:37`. Resolver needs (a) per-call-site closure tracking across two `func()`-typed parameter passes (the parameter is never stored, only immediately launched, so the value uniquely flows through) and (b) treating `go f()` as a call edge despite the asynchronous boundary.
