- **Path length:** 11 steps
- **Edge types encountered:** `direct-function-call`, `function-value-in-struct-field`, `method-call-on-concrete-type`, `struct-literal-field-assignment`, `http-handler-registration`, `interface-method-dispatch`
- **Hardest edge:** Step 7's `interface-method-dispatch` from the `net/http.Server` through `gorilla/mux.Router` to the `*web.Handler` registered for `POST /api/v4/commands/execute`. The dispatch crosses the `http.Handler` interface twice (once at the server, once at the mux route) and is keyed on a runtime-matched URL pattern; resolving it statically demands modeling gorilla/mux's path-table as a registry of `http.Handler` values keyed by string patterns and method, then linking that table back to the registration site in `InitCommand`. - **Static-analysis feasibility:** Feasible end-to-end with a precise, field-sensitive call-graph analysis that (a) models `init()`-time registrations into the cobra command tree and the gorilla/mux routing table, and (b) tracks function values stored in struct fields (`cobra.Command.RunE`, `web.Handler.HandleFunc`) through to their invocation sites. There is no `reflect`, plugin, or runtime-supplied function pointer on this path, so the chain is statically resolvable in principle.
