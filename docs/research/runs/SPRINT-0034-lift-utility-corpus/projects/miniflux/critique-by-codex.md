# Critique of miniflux drafts by codex

## Verdicts on claude's draft

| Candidate ID | Verdict | One-paragraph reasoning |
|---|---|---|
| C-1 (`RefreshFeed`) | KEEP | rubric criterion satisfied: latency / failure. This is the canonical background feed-refresh unit: worker-driven, payload and network dominated, and naturally retryable by the next refresh cycle; the broad dependency closure is a risk, not a disqualifier. |
| C-2 (`ProcessFeedEntries`) | KEEP | rubric criterion satisfied: compute envelope. The per-entry loop contains URL cleanup, optional scraping, rewrite/filter passes, sanitization, and reading-time work, so cost scales with feed size and crawler settings; the in-place feed mutation is manageable if treated as an in/out value. |
| C-3 (`ScrapeWebsite`) | KEEP | rubric criterion satisfied: coherent unit. It is narrower than full entry-page processing but captures the remote fetch plus custom-rule/readability extraction behind a clean `(requestBuilder, URL, rules)` contract, with callers in both background refresh and explicit user fetch-content paths. |
| C-4 (`SanitizeHTML`) | KEEP | rubric criterion satisfied: state independence. This is a pure payload transform over raw HTML with stable config reads only; call granularity may be fine, but large entries and batch refreshes make it a legitimate low-risk lift target. |
| C-5 (`iconChecker.UpdateOrCreateFeedIcon`) | KEEP | rubric criterion satisfied: compute envelope. Discovery, image decode/resize/re-encode, SVG minification, hashing, and storage are real per-feed work; keep it lower ranked because load is mostly creation/forced-refresh bursts. |
| C-6 (`integration.PushEntries`) | KEEP | rubric criterion satisfied: latency / failure. It is already launched asynchronously after refresh persistence and fans out to external providers based on entry batch size and enabled integrations, which is exactly the async IO-bound shape the rubric admits. |
| C-7 (`integration.SendEntry`) | KEEP | rubric criterion satisfied: latency / failure. The save-entry integration fan-out is value-parameterized and invoked from goroutines across REST, UI, Fever, and Google Reader surfaces, so remote failure is already outside the synchronous response contract. |
| C-8 (`subscriptionFinder.FindSubscriptions`) | KEEP | rubric criterion satisfied: compute envelope. The OPML-import rationale is overstated because OPML import does not call this path, but the candidate itself still does outbound fetches, HTML/feed detection, YouTube/RSS-Bridge/well-known probes, and has bounded per-call state. |
| C-9 (`OPML Handler.Import`) | KEEP | rubric criterion satisfied: coherent unit. This is a low-ranked but real rare-heavy import candidate: XML parse and per-subscription DB writes are synchronous and not as compelling as refresh, yet the `(userID, io.Reader)` boundary is clean and large imports can spike. |
| C-10 (`mediaproxy.RewriteDocumentWithAbsoluteProxyURL`) | KEEP | rubric criterion satisfied: coherent unit. Keep only as a marginal, oracle-gated candidate: the string-to-string function is clean and list reads can multiply work, but the request-path latency concern is real and a batched page-level invocation would be preferable. |
| C-11 (`oauth2.googleProvider.Profile` / `oidcProvider.Profile`) | KEEP | rubric criterion satisfied: coherent unit. This is lower-volume than feed work, but it matches the rubric's OAuth calibration case: stable provider config, token exchange/profile fetch, OIDC verification, and an interface-method boundary. |
| C-12 (`mediaProxy`) | DROP | Fails compute envelope and latency / failure. The handler is a streaming reverse proxy whose primary effect is forwarding an origin response body inline to a browser resource request, so an extra hop worsens first-byte and body streaming behavior rather than offloading meaningful application compute. |

## Overlooked

None.

## Overall observations

Both foreign drafts converge cleanly on the real Miniflux hot path: feed refresh, per-entry processing, scraping/readability, sanitization, parsing, icons, and integration fan-out. Claude is stronger on rubric tradeoffs and line accuracy, and its extra OAuth candidate is a plausible low-ranked interface-method specimen. Gemini identifies many of the right regions but is systematically weaker on citation rigor and sometimes treats pure or frequent helpers as useful even when the compute envelope is too small to amortize a remote call.
