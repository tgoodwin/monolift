### Summary

- **Path length:** 11 steps from `main()` to `(*SMTPClient).send`.
- **Edge types encountered:** `method-call-on-concrete-type`, `struct-literal-field-assignment`, `function-value-in-struct-field`, `direct-function-call`, `closure-passed-as-argument`, `interface-method-dispatch`.
- **Hardest edge:** Step 10 — the `e.Mailer.Send` interface dispatch combined with the closure handoff through `Hook.Trigger`. The `Mailer` interface has two concrete implementations (`*SMTPClient`, `*Sendmail`) selected at runtime by `app.Settings().SMTP.Enabled` inside `(*BaseApp).NewMailClient`; static analysis must keep both edges live since the choice is a settings-driven boolean, not a build-time selection. Step 8 (route registration → `http.ServeMux` → `http.Server.Serve` invocation) is a close runner-up because the function value `recordRequestEmailChange` traverses three abstraction layers (`Route.Action` → `loadMux` closure → `ServeMux` map) before being called.
- **Static-analysis feasibility:** Resolvable end-to-end with whole-program type analysis (CHA/RTA) plus a points-to / call-graph pass that tracks function values through struct fields, slices, and maps. There is no reflection, no plugin loading, and no runtime-determined function pointer along this path. **Alternative paths:** the same `(*SMTPClient).send` is reachable from four other HTTP routes registered in `bindRecordAuthApi` (`request-password-reset`, `request-verification`, `request-otp`, plus `auth-with-password` via the new-device alert in `apis/record_helpers.go:633`) and from the `forms.TestEmailSend` admin form (`forms/test_email_send.go:105-114`). Three of those routes wrap the call in `routine.FireAndForget` (e.g. `apis/record_auth_password_reset_request.go:56`), adding a `goroutine-launch` edge but no new resolution problem. The JSVM bindings at `plugins/jsvm/binds.go:699-703` expose the `mails.SendRecord*` functions to user-supplied JavaScript: that path crosses a `goja.Runtime` and is **not statically resolvable** (the call originates from interpreted source loaded from `pb_hooks/`), so a compiler must treat any JSVM hook as a dynamic boundary and stop the trace at the binding registration.
