### Summary

- **Path length:** 12 steps from `main` to the region root.
- **Edge types encountered:** `method-call-on-concrete-type`, `struct-literal-field-assignment`, `function-value-via-struct-field`, `direct-function-call`, `method-value-as-callback`, `closure-capture`, `goroutine-launch`.
- **Hardest edge:** Step 8 (the router → `mux.HandleFunc` → `Hook.Trigger` chain). It combines (i) a `Route.Action` field flow set at registration and read inside `loadMux`, (ii) registration into Go's `net/http.ServeMux` whose dispatch is URL-pattern-driven at runtime, and (iii) a chain of nested `nextFunc` closures inside the hook before the action is actually called. Resolving "which `download` will run for which URL" needs whole-program tracking of `Route.Action` assignments combined with the assumption that `ServeMux` will invoke any registered `HandlerFunc`. By contrast, Step 11 (`singleflight.DoChan`) is conceptually similar but shorter: it requires a single framework-summary edge stating that the function value passed to `DoChan` is invoked exactly once.
- **Static-analysis feasibility:** Fully feasible with type-based whole-program call-graph analysis plus a small set of framework summaries — specifically: (a) cobra's `Command.RunE` is invoked by `Command.Execute`, (b) `http.ServeMux.HandleFunc` registers handlers that `Server.Serve` will call, and (c) `singleflight.Group.DoChan` invokes its `fn` argument once. There is **no reflection, no plugin loader, and no runtime function-pointer table** on the path; every edge is a closure, struct-field read, method value, or direct call resolvable from the source tree. Alternative routes were considered and discarded: `CreateThumb` has only **one** non-test caller in the repo (`apis/file.go:225`), so this HTTP-driven path is also the *only* path. There is no cron / hook / CLI alternative.
