### Summary

- **Path length:** 13 steps
- **Edge types encountered:** `method-call-on-concrete-type`, `command-callback-registration`, `direct-function-call`, `http-handler-registration`, `finite-switch-direct-call`, `interface-method-dispatch`, `config-guarded-interface-implementation`, `hook-trigger-one-off-callback`, `hook-finalizer-method-call`
- **Hardest edge:** Step 13 is the hardest local edge because `SMTPClient.Send` reaches the region through a hook chain populated during mailer construction, and the analyzer must connect `Hook.Trigger`'s one-off finalizer plus the registered app-level hook's `e.Next()` continuation to `c.send`.
- **Static-analysis feasibility:** The selected path is statically resolvable with whole-program type analysis plus models for Cobra command callbacks, router registrations, and PocketBase's generic hook chain; the path is conditional on running the `serve` command, receiving `POST /api/settings/test/email`, selecting the `verification` template, and having SMTP enabled, but there is no reflection or plugin boundary on this path.
- **Alternatives:** Record auth APIs such as password reset, verification, OTP, email change, and auth-alert also reach the same mail helpers, but they add auth-specific hooks and often goroutine callbacks before entering `mails.SendRecord*`. User JS hooks can expose mail sending too, but those depend on user-supplied hook scripts and are not the shortest static source path.
