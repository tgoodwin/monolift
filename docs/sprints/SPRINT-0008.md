# SPRINT-0008 — Educational static site via GitHub Pages

**Status:** planned
**Scope:** advisor-facing static educational site for Monolift's design story, built with MkDocs + Material and deployed to GitHub Pages at `https://tgoodwin.github.io/monolift/`.

## Intent

SPRINT-0007 landed the canonical-shape classifier and state-class inference, but the design rationale is still hard to read unless the reader already knows the codebase and the ADR trail. The author and his PhD advisors need one stable, educational artifact that shows why Monolift is shaped the way it is after the corpus work — which real Go constraints forced each decision, where the current compiler logic lives, and how the v1→v2 arc unfolded.

This sprint ships that artifact as a zero-JS static site. It tells the story through four load-bearing content sections (canonical shapes → state-class inference → refusal-diagnostic framework → v1→v2 arc), each pairing live Monolift compiler code with a curated excerpt from the evaluation corpus (Caddy, Pocketbase, Miniflux) that illustrates the constraint the design accommodates. Snippets are drift-checked in CI so the site cannot silently diverge from the implementation or from upstream targets.

## Goals

- One deployable artifact at `https://tgoodwin.github.io/monolift/` that reads as a coherent 30–45-minute design-story walkthrough.
- Every page claim about compiler behavior is backed by a live, drift-checked snippet from `pkg/compiler/**`.
- Every load-bearing section pairs a Monolift snippet with a real target-codebase snippet that shows the Go constraint the design responds to.
- Snippet provenance (upstream repo, pinned SHA, path, line range, SPDX license, fetch date) is preserved inline on every vendored external excerpt, and every `pkg/compiler/**` snippet is anchored to named markers so drift failures resolve to a minimal author-ready patch rather than noisy manual rework.
- CI fails on: Monolift source-range drift, vendored external excerpt drift against pinned upstream SHAs, policy violations (extra JavaScript, Graphviz, D2, non-Material diagram plugins), broken internal links, strict-build warnings.
- A reader who has read the PLOS '25 paper can land on the index and follow the arc without asking the author questions.

## Non-goals

- Per-shape adapter templates, framework-handler predicates, or any other SPRINT-0009+ compiler implementation work.
- `reportv2` schema deep-dive, harness deep-dive, or stubcompiler deep-dive beyond the minimal context the refusal-diagnostic section requires.
- Interactive notebooks, embedded playgrounds, video walkthroughs, slide decks.
- Graphviz, D2, hand-authored SVG, Tailwind, or custom JavaScript beyond what `mkdocs-material` ships by default.
- Moving ADRs into the site — they remain canonical under `docs/decisions/` and are linked by URL.
- Restating ADR content or `docs/evolution.md` chronology; link instead.
- API reference autogenerated from Go.
- A glossary as a separate page (tuck one-line term definitions inline in the sections that develop them).
- Custom theme, analytics, branding work (logo, UCSC colors) — Material defaults only.

## Technical decisions (committed in this plan)

- **Stack:** MkDocs + `mkdocs-material`. Rejected alternatives: Hugo / Docusaurus / Zola (would fight with the Python snippet tooling); custom Jinja macro (same drift problem at higher implementation cost); `go/ast` symbol-based extraction (drags a Go runtime into docs CI).
- **Snippet include mechanism:** `pymdownx.snippets` with line-range syntax (`--8<-- "path:Lstart:Lend"`). No `mkdocs-macros-plugin`.
- **Monolift source anchoring:** `// site:begin NAME` / `// site:end NAME` comments in `pkg/compiler/**/*.go` around each referenced range. The drift-check resolves the marker pair to a line range and fails if the Markdown include's range disagrees; a companion fix script rewrites the ranges in-place. This is the single biggest ergonomic decision — without the fixer, drift failures become noisy and get silenced.
- **External excerpts:** vendored `.go.txt` files under `docs/site/snippets/external/<project>/<filename>.go.txt` (note `.go.txt`, not `.go`, so `go build ./...` and `gopls` ignore them). Provenance header on every file: upstream repo, pinned SHA (matching `evaluation/MANIFEST.yaml`), upstream path, line range, SPDX license, fetch date.
- **External snippet refresh:** `scripts/refresh-external-snippets.py` reads `evaluation/MANIFEST.yaml` and a new `docs/site/snippets/external/excerpts.yaml`, fetches upstream at pinned SHA via `git archive` (no dependency on the gitignored `evaluation/` clone), slices the range, prepends the provenance header, writes to the vendored path. CI re-runs this and fails if the working tree is dirty.
- **Site root:** `mkdocs.yml` at repo root with `docs_dir: docs/site` and `site_url: https://tgoodwin.github.io/monolift/`. Keeps `/monolift/` base-path correct and keeps the top-level intent visible.
- **Layout:** side-by-side code pairings use a responsive CSS grid in `docs/site/assets/stylesheets/monolift.css`; desktop is two-column, mobile collapses to one. No tabs, no custom JavaScript.
- **Deployment:** one workflow `.github/workflows/docs-site.yml` with two jobs — `build` (runs on `pull_request` and `push`; drift-check, refresh-verify, `mkdocs build --strict`, lychee linkcheck, artifact upload) and `deploy` (runs only on `push` to `main`, depends on `build`, uses `actions/configure-pages` + `actions/upload-pages-artifact@v3` + `actions/deploy-pages@v4` with `concurrency: { group: "pages", cancel-in-progress: false }`).
- **Policy guard:** `scripts/check-docs-policy.py` grep-scans `mkdocs.yml` and `docs/site/**` for disallowed patterns (`extra_javascript:`, `mermaid2`, Graphviz/D2 references, hand-authored SVG). CI fails if any are introduced.
- **Toolchain:** Python-only for docs tooling. One `docs/site/requirements.txt` pinning `mkdocs`, `mkdocs-material`, `pymdown-extensions`, plus whatever YAML/HTTP libs the scripts need. No Go toolchain in the docs pipeline.
- **Makefile targets** as the stable interface for local and CI: `make docs-site-refresh`, `make docs-site-verify`, `make docs-site-build`, `make docs-site-serve`, `make docs-site-check-drift`, `make docs-site-check-policy`. Workflow YAML invokes these targets rather than re-implementing commands.
- **ADR-0017** lands as part of this sprint, recording the site-build decision, the marker-based drift strategy, and the refusal to introduce a second documentation runtime (notebooks, videos, JS-heavy widgets).

## Site information architecture (frozen)

Six pages, navigation order fixed:

1. **`index.md`** — orientation. One paragraph stating the site's audience and scope; section cards linking to the four load-bearing pages; links to the paper, the ADR directory, and `docs/evolution.md`.
2. **`canonical-shapes.md`** — the shape classifier.
3. **`state-class-inference.md`** — the evidence-precedence rule stack.
4. **`refusal-diagnostics.md`** — the `MLV2_*` refusal framework and diagnostic translation.
5. **`v1-to-v2.md`** — the arc from v1 pragmas to the v2 contract.
6. **`reading-guide.md`** — a single appendix page: how to navigate `pkg/compiler/`, the ADR index table (static — no autogeneration), where `evolution.md` sits. No separate glossary; inline one-line definitions in the sections that develop terms.

Every load-bearing page (§2–§5) follows the same structure:

- One opening paragraph framing the design pressure.
- One mermaid diagram.
- A side-by-side code pairing: one Monolift snippet (included by `pymdownx.snippets`, anchored by `site:begin/end` markers) + one target-codebase snippet (vendored `.go.txt` with provenance header).
- A closing "Why we did this" note of ≤3 sentences linking to the relevant ADR numbers and `docs/evolution.md`. No ADR content restated.

Section 4 (`v1-to-v2.md`) resolves the "no natural external pair" issue by showing the **same target** processed under the v1 contract versus the v2 contract — the contrast is the pairing. Miniflux or Caddy is the candidate, chosen in Phase 0 against the committed `docs/specs/monolift-v2-contract.md`.

## Scope boundaries

**In scope:**
- `mkdocs.yml`, `docs/site/` tree, theme configuration, CSS, Makefile targets, GitHub Actions workflow.
- The six pages listed above, no more.
- Snippet manifest, refresh script, drift-check script, fix script, policy-guard script, committed snippet outputs under `docs/site/snippets/{external,generated}/`.
- Vendored curated excerpts from pinned external targets (Caddy, Pocketbase, Miniflux; others only if a pairing actually needs them).
- `docs/site/CONTRIBUTING.md` documenting the author workflow (how to add a section, anchor a snippet, refresh external excerpts, the manual repo-settings step).
- Minimal `// site:begin NAME` / `// site:end NAME` markers in `pkg/compiler/**/*.go` at exactly the anchor points the site references.
- ADR-0017 and a one-paragraph entry in `docs/evolution.md` linking the deployed site.
- Root `README.md` gains one line pointing at the deployed URL.

**Out of scope:**
- Any `pkg/compiler/` change beyond the site anchor markers.
- Folding any spec into the site (spec lives in `docs/specs/`, site links to it).
- Additional pages beyond the six listed. Glossary/reading-guide expansion beyond one page.
- Graphviz, D2, custom JS, custom theme, analytics, logo work.
- Dependence on the gitignored `evaluation/` clones being present in CI.
- Changes to `docs/sprints/ledger.yaml` during execution (ledger updates are orchestrator-driven).

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Monolift source refactor produces noisy drift failures; authors start bypassing the check | `site:begin NAME` / `site:end NAME` markers pin anchors independently of line numbers; `scripts/fix-snippet-drift.py` produces a minimal author-ready patch; check emits copy-pasteable diffs not walls of error text. **Most load-bearing mitigation in the plan.** |
| "Seven-rule precedence" page framing disagrees with implementation or ADR-0016 | Phase-0 reconciliation is an explicit blocker task before any Phase 3 prose lands; if sources disagree, resolve in code/ADR or rewrite the page framing before writing prose |
| CI accidentally depends on the gitignored `evaluation/` clone | Refresh script fetches upstream by pinned SHA via `git archive`-equivalent against a CI-recreatable cache; never reads from `evaluation/` in CI; Phase-1 task explicit about this boundary |
| GitHub Pages base-path `/monolift/` breaks assets, mermaid rendering, or internal links | `site_url: https://tgoodwin.github.io/monolift/` set in mkdocs.yml; Phase 7 first-deploy verification against the live URL is a required acceptance task |
| Prose bloat — site becomes a second spec | One-paragraph-per-opening + 3-sentence "why we did this" limits enforced at review; ADRs linked, never restated; `docs/evolution.md` linked, never re-narrated; Phase 6 prose-discipline review pass |
| Scope creep: glossary, ADR index autogeneration, per-package API reference | Non-goals section calls these out explicitly; reading guide capped at one page; ADR index is hand-maintained static table, not generator |
| License non-compliance on vendored excerpts | Provenance header schema requires SPDX tag; Phase 8 spot-check task verifies one file per project; Apache-2.0 / MIT all permit attributed excerpts |
| First deploy fails on manual "enable Pages" repo-settings step | Phase 7 explicit task + `CONTRIBUTING.md` documents the one-time click |
| v1→v2 section has no natural target-codebase pair | Resolved by showing the same target handler under v1 vs v2 framing (committed in the IA section); Phase 0 picks the specific target |
| `docs/specs/monolift-v2-contract.md` not committed when Phase 5 starts | Phase 5 explicit prerequisite task; if blocked, stop and surface |
| Mermaid rendering tempts "just add one plugin" creep | Material's built-in mermaid fence is used; `scripts/check-docs-policy.py` fails CI on `mermaid2` or `extra_javascript` additions |
| Deploy latency or overlapping deploys on rapid pushes | `concurrency: { group: "pages", cancel-in-progress: false }` serializes queued deploys; Phase 8 dry-run verifies |
| `pymdownx.snippets` range syntax doesn't behave as expected with the project structure | Phase 2 is a full mechanism rehearsal on one section before scaling to four; if `snippets` misbehaves, fallback is a tiny custom Markdown preprocessor (not the full macro stack) — scoped to 0.5 day |
